
# 恋愛モビー占い 設計書

## 1. 前提

恋愛モビー診断は、診断結果を入口にしてキャラクターIPへの接触回数を増やすコンテンツとして扱う。
占い機能は「当たる/当たらない」よりも、毎日または毎月サイトへ戻る理由を作るための機能である。

今回の仕様では、以下を採用する。

- 日次占い：毎日表示。30日分×16タイプの固定コンテンツを持つ。
- 月次占い：月初に大きく表示。保存・共有・診断リンク共有の起点にする。
- キーパーソン表示：恋愛相性表とは別の占い用テーブルを使う。
- 毎日ミッション：日次占いに必ず出す。
- お世話機能：今回は実装しない。
- なかよし度：今回は実装しない。

## 2. 恋愛相性表との切り分け

既存の相性表は恋愛分野での相性判定として扱う。
占い画面では、相性表を直接「最高相性」「恋人向き」として表示しない。

占いでは以下のように言い換える。

| 目的 | 表示名 | 意味 |
|---|---|---|
| 診断共有を促す | 今日のキーパーソン | 今日の流れを動かす可能性があるタイプ |
| 行動を促す | 助けてくれるかも | 相談・雑談・きっかけ作りに使えるタイプ |
| 拡散を促す | このタイプかも？ | 相手に診断リンクを送るための口実 |

NG表現。

- 今日の運命の相手
- 結婚相性がいい人
- 恋人にすべきタイプ
- あなたと最高相性

OK表現。

- 今日のキーパーソン
- 助けてくれるかも
- 背中を押してくれるかも
- 空気を変えてくれるかも
- あなたの気づきを増やしてくれるかも

## 3. ユーザーフロー

1. ユーザーが診断を完了する。
2. typeCode / typeName を localStorage またはアカウント情報に保存する。
3. 結果ページに「今日の恋愛モビー便り」導線を出す。
4. 日次占いページで、今日の状態・恋予報・ミッション・キーパーソンを表示する。
5. キーパーソン欄に「このタイプかも？診断を送る」を表示する。
6. 月初には「月刊恋愛モビー予報」を表示する。
7. 月間カードを保存・共有できるようにする。

## 4. 日次占い仕様

### 4.1 表示項目

- 今日の状態
- 恋予報スコア
- 今日のテーマ
- モビーからのメッセージ
- 今日のミッション
- 今日のキーパーソン
- ラッキーアイテム
- 診断共有文

### 4.2 コンテンツ量

- 16タイプ × 30日分 = 480本。
- 各タイプ内では30日間テーマとミッションを重複させない。
- 31日目は「月末ボーナス」または「翌月予告」にする。

### 4.3 日付ロジック

```ts
const dayIndex = new Date().getDate();
if (dayIndex <= 30) {
  contentIndex = dayIndex;
} else {
  contentIndex = 'bonus';
}
```

月をまたいだ時に同じ Day 01 が出てもよいが、月間テーマの文脈を変えることで新鮮さを出す。

## 5. 月次占い仕様

### 5.1 表示項目

- 今月の企画名
- 今月の恋テーマ
- 今月のモビー状態
- 月間恋予報スコア
- 恋が動く日
- 注意したい日
- 今月のミッション
- 今月のキーパーソン
- 保存カード文
- 診断共有文

### 5.2 役割

月次占いは、日次よりも以下を重視する。

- 保存したくなる。
- SNSに出したくなる。
- 月初に見に来る理由になる。
- 診断リンクを誰かに送る理由になる。

## 6. キーパーソン共有導線

### 6.1 表示例

```text
今日のキーパーソン：恋に旗を振る人モビー
あなたの背中を押してくれるかも。
このタイプかも？と思う人に診断を送ってみる。
```

### 6.2 共有文例

```text
今日の私のキーパーソン、恋に旗を振る人モビータイプかも。
あなた何タイプ？診断してみて。
```

URL例。
